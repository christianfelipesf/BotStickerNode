1) RESOLUÇÃO ORIGINAL
--------------------
Arquivo: src/services/rankImage.js:69,152-159
- W lógico = 1080px
- H lógico Top10 = HEADER_H(210) + 10*ROW_H(72) + FOOTER_H(70) + PAD(32) = 1032px

- H efetivo Top10 = 1032 * 3.055 = ~3153px (10.4 MPixels, ~41.6MB RAM só do bitmap + composite ~80-100MB pico)
- Formato: PNG 32-bit, 900KB-1.8MB no disco/rede (com avatares JPEG reais)

Comando: src/commands/rank.js:151 envia como { image: imgBuffer } — WhatsApp converte image para JPEG opaco de qualquer forma.

2) POR QUE MUDOU
----------------
- WhatsApp reescala qualquer imagem com lado maior >1600px para 1600px com JPEG q~70 e >2048px com downscale bilinear — enviar 3300px faz o servidor descartar 75% dos pixels e recomprimir com borrão duplo + artefato.
- Preview na conversa é 90-120px thumb; ao abrir, largura útil é 360-412dp (Android). >1080px já é >2-3x retina, olho não distingue.
- PNG com rx:24/gradient vira fundo sólido no JPEG do WA; enviar JPEG direto economiza ~40% e evita flatten.
- Custo anterior: ~42MB + composite ~85MB por !rank, 900KB-1.8MB upload para ser jogado fora. Comp. PNG de 10MP leva ~600ms extra.
- Legibilidade: em 3300px, fontes 38pt→116px / 26pt→79px — oversampling inútil. Em 1080px nativo (1x) já é perfeitamente nítido.
