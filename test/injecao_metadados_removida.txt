3. POR QUE FOI ALTERADO / REMOVIDO EM PARTE
------------------------------------------
Problema reportado: "!s em imagem gera sem author/pack, em video gera certo"
Log do caso real:
  [10:09:07] handleMediaCommand sticker input mime=image/jpeg bytes=66736 from=... by=Gravity 🪐 pack="Gravity 🪐" author="Antigravity Bot🪐" explicit={}
  [STICKER-LOG] addMetadata: embutindo original 66736B base64=88984 testLen=107237
  [STICKER-LOG] addMetadata: final 107288B (webp 18088 + exif 89173) exifLen=89173

O handleMediaCommand gerou pack/author CORRETOS, o log confirma, e o EXIF também
continha "sticker-pack-name":"Gravity 🪐" no preview. Porém no WhatsApp o sticker
apareceu sem pack/author.

Causa raiz: exif 89KB é gigante. WhatsApp espera exif ~150-200 bytes. Clientes
truncam/ignoram exif muito grande e exibem pack vazio. Vídeo (exif 137-155 bytes,
sem data) exibia normal, mascarando o bug.

Histórico de limites:
  - Original: <500KB original, <950KB total -> exif 100KB+ frequente (ex: 96KB imagem -> 128KB exif)
  - Primeira correcao (2026-09-08 12:00): <80KB / <150KB -> ainda permitia 66KB -> 89KB exif, bug persistiu
  - Correcao atual: <25KB / <50KB total

5. COMO FUNCIONA AGORA (POS-CORRECAO)
------------------------------------
Cenário A - Imagem pequena (<25KB, ex: ícone 6KB):
  mediaToSticker -> sharp webp 558B -> addMetadata com data -> webp 9060B exif 8476 (data presente)
  stickerToMedia -> detecta _exifJson.data -> retorna original 6223B idêntico, mime image/jpeg, sem recompressao
  !toimg devolve JPEG original perfeito.

Cenário B - Imagem média/grande (>25KB, maioria dos casos reais: 66KB, 90KB, 300KB):
  mediaToSticker -> sharp webp -> addMetadata SEM data (testLen >50KB ou original >25KB) -> webp ~18-65KB exif ~150B
  stickerToMedia -> não encontra data -> fallback sharp: sharp(buffer).png() -> PNG sem perda adicional além do webp inicial
  !toimg devolve PNG decodificado do webp (leve perda vs original, mas pack/author sempre visível)

Cenário C - Vídeo:
  Inalterado: ffmpeg webp -> addMetadata sem data -> exif 140B
